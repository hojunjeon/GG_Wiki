# Ingest 프롬프트

## 사용법
```bash
codex "$(cat prompts/ingest.md)"
```

---

먼저 `AGENT.md`를 읽고 위키 구조와 규칙을 완전히 파악해라.

그 다음 아래 순서대로 Ingest 작업을 수행해라.

---

## 요약 작성 기준 (필독 — 모든 페이지에 적용)

이 위키의 독자는 **IT/AI 트렌드를 추적하는 SW 개발자**다.
요약은 아래 두 가지를 반드시 답해야 한다:

1. 이 항목이 기존과 **무엇이 다른가** (무엇이 새로운가)
2. 실제 개발자에게 **어떤 실용적 의미**가 있는가

단순한 원문 재서술은 요약이 아니다. "주목받고 있다", "중요하다" 같은 공허한 표현은 쓰지 않는다.

### "왜 중요한가" 섹션 작성 기준

아래 중 이 소스에 가장 맞는 것을 골라 1~2줄로 답해라:

- 기존 방식 대비 **무엇을 개선**하는가
- 어떤 **개발자 문제**를 해결하는가
- 현재 트렌드 흐름에서 **어떤 위치**를 차지하는가

### 소스 파일 노이즈 처리

원본 파일에는 사이트 네비게이션, 툴팁 설명("What is X?"), 광고성 텍스트 등이 포함될 수 있다.
본문 핵심 내용만 사용하고 나머지는 무시해라.

## 작업 순서

### 1. 미처리 소스 파일 식별

`wiki/log.md`를 읽어 이미 처리된 소스 파일 목록을 확인해라.
`sources/` 폴더를 스캔해서 `log.md`에 없는 신규 파일 목록을 만들어라.
신규 파일이 없으면 "처리할 새 항목 없음"을 출력하고 종료해라.

### 2. 각 신규 파일 처리

신규 파일 하나씩 아래 단계를 수행해라.

**a. 소스 요약 페이지 생성**
- `wiki/sources/{원본파일명}.md` 파일을 생성해라.
- AGENT.md의 sources/ 페이지 형식을 따라라.
- 위 "요약 작성 기준"을 반드시 지켜라.

**b. entities/ 또는 concepts/ 페이지 업데이트**
- 소스에 등장한 기술·개념이 `wiki/entities/` 또는 `wiki/concepts/`에 이미 있으면 해당 페이지 하단 "관련 페이지" 섹션에 새 소스 링크를 추가해라.
- 없으면 아래 기준으로 신규 생성 여부를 판단해라:
  - `wiki/log.md`에서 같은 기술·개념이 **2회 이상** 등장했다면 신규 페이지를 생성해라.
  - 처음 등장이지만 독립적으로 다룰 만큼 중요한 개념이라면 생성해라.
  - 처음 등장하고 독립 페이지가 불필요하면 소스 페이지 frontmatter의 tags에 후보 키워드로 남겨라.

**c. index.md 갱신**
- `wiki/index.md`를 열어 새로 생성된 페이지를 알맞은 카테고리 아래에 추가해라.
- 형식: `- [[wiki/sources/{파일명}]] — {1줄 요약}`
- 상단 "마지막 업데이트" 날짜와 "총 페이지 수"를 갱신해라.

**d. log.md 기록**
- `wiki/log.md` 상단에 아래 형식으로 한 줄 추가해라.
- `## [YYYY-MM-DD] ingest | {소스 제목}`

### 3. 완료 보고

처리한 파일 수, 생성한 위키 페이지 수, 업데이트한 페이지 수를 출력해라.
독립 페이지 생성이 필요해 보이는 개념이 있으면 목록으로 함께 출력해라.
